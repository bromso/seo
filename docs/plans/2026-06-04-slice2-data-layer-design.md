# Slice 2 — Data Layer Design

**Status:** approved
**Date:** 2026-06-04
**Predecessor:** [`2026-06-04-audit-packages-slice1-design.md`](2026-06-04-audit-packages-slice1-design.md)
**Scope:** Persist `AuditResult` outputs from slice 1 into Supabase Postgres via Drizzle ORM. No runner, no queue, no dashboard.

## Goal

Stand up the data layer that consumes the stable `AuditResult` contract from `@repo/audit-core`. After this slice, the next layer (runner in slice 3) can write `AuditResult` rows from the queue, and the layer after that (dashboard in slice 4) can read them back with full RLS isolation.

A successful slice 2 is:

```bash
supabase start
bun --filter @repo/db migrate
bun --filter @repo/db seed              # creates a test user + site + a sample run
bun --filter @repo/db test              # unit tests
RUN_INTEGRATION=1 bun --filter @repo/db test  # RLS + trigger integration tests
```

## Scope decomposition (predecessor recap)

The original platform brief covers ~8 subsystems. Slice 1 shipped the audit packages + CLI. Slice 2 ships the data layer only. The remaining slices, in order:

1. ✅ Audit packages + CLI (slice 1)
2. **This slice.** Supabase schema + RLS + `@repo/db` (Drizzle).
3. Runner app, pgmq, Realtime broadcast.
4. Web dashboard (single-site MVP).
5. Multi-site / competitor comparison.
6. PWA + workers.
7. Remaining audit packages (a11y, structured, social, links, security).
8. Scheduling, K8s, ops.

## Out of scope for slice 2 (explicit)

The runner app, pgmq + queueing, Realtime broadcast hookup, scheduling (cron), the dashboard, auth UI, generated TS types from Supabase (we use Drizzle's inferred types, not `supabase gen types`), seeding production data, an `audit_categories` table (the count-of-5 in the run-status rollup trigger is a constant for slice 1's category set; it migrates when slice 7 adds new categories).

## Architecture decisions summary

| # | Decision | Choice |
|---|---|---|
| 1 | Local dev environment | Supabase CLI (Docker stack): `supabase start` gives Postgres + Auth + Realtime + Storage + Studio. |
| 2 | Migration tooling | Drizzle is the source of truth. `drizzle-kit generate` emits SQL; `drizzle-kit migrate` applies against `DATABASE_URL`. Supabase CLI is used only for the local stack, not for migrations. |
| 3 | Self-site cardinality | Exactly one self-site per user (slice 2 MVP). Enforced via partial unique index. Polymorphic / explicit-groups schema is deferred to a later slice. |
| 4 | Cross-user audit dedup | None. Each user's audits are private. The cross-user competitor graph is queryable from the `sites` table without sharing audit data. Canonical-site dedup is deferred. |
| 5 | RLS strategy for nested tables | Denormalize `owner_id` onto `audit_runs` and `audit_results`. Populated by `BEFORE INSERT` triggers. RLS policies are single-column checks (no joins). |
| 6 | `audit_runs.status` rollup | Stored column; recomputed by an `AFTER INSERT` trigger on `audit_results`. |
| 7 | Raw + partial reasons storage | `raw` → `jsonb` column (opaque). `partial_reasons` → `text[]` column (queryable). |
| 8 | `@repo/db` surface | Thin: Drizzle client factory + table schemas + `auditResultToInsert` mapping + `canonicalUrl`. No generic repository layer. |

A `profiles` row is auto-created by a `SECURITY DEFINER` trigger on `auth.users` INSERT (the canonical Supabase pattern).

### `sites`

```ts
export const sites = pgTable("sites", {
  id: uuid("id").primaryKey().defaultRandom(),
  ownerId: uuid("owner_id").notNull()
    .references(() => profiles.id, { onDelete: "cascade" }),
  url: text("url").notNull(),                       // raw user input (preserved)
  normalizedUrl: text("normalized_url").notNull(),  // canonicalUrl(url)
  label: text("label"),
  isCompetitor: boolean("is_competitor").notNull().default(false),
  createdAt: timestamp("created_at", { withTimezone: true })
    .notNull().defaultNow(),
}, (t) => ({
  uniqOwnerNormalized: uniqueIndex("sites_owner_normalized_url_idx")
    .on(t.ownerId, t.normalizedUrl),
  uniqOwnerSelf: uniqueIndex("sites_one_self_per_owner_idx")
    .on(t.ownerId)
    .where(sql`is_competitor = false`),
  ownerIdx: index("sites_owner_idx").on(t.ownerId),
}))
```

The partial unique index `sites_one_self_per_owner_idx` enforces "exactly one self site per user." Future slices that need to relax this drop the partial index in a migration.

### `audit_runs`

export const auditRuns = pgTable("audit_runs", {

### `audit_results`

```ts
export const auditResults = pgTable("audit_results", {
  id: uuid("id").primaryKey().defaultRandom(),
  runId: uuid("run_id").notNull()
    .references(() => auditRuns.id, { onDelete: "cascade" }),
  ownerId: uuid("owner_id").notNull()
    .references(() => profiles.id, { onDelete: "cascade" }),  // denorm
  category: categoryEnum("category").notNull(),
  status: resultStatusEnum("status").notNull(),
  score: integer("score"),                          // 0..100, NULL when failed
  issues: jsonb("issues").$type<Issue[]>(),         // NULL when failed
  raw: jsonb("raw"),                                // NULL when failed
  partialReasons: text("partial_reasons").array(),  // NULL unless partial
  errorCode: text("error_code"),                    // NULL unless failed
  errorMessage: text("error_message"),
  errorRetryable: boolean("error_retryable"),
  packageName: text("package_name").notNull(),
  packageVersion: text("package_version").notNull(),
  durationMs: integer("duration_ms").notNull(),
  startedAt: timestamp("started_at", { withTimezone: true }).notNull(),
}, (t) => ({
  runCategoryUniq: uniqueIndex("audit_results_run_category_idx")
    .on(t.runId, t.category),
  ownerCategoryStartedIdx: index("audit_results_owner_category_started_idx")
    .on(t.ownerId, t.category, t.startedAt.desc()),
  scoreCheck: check(
    "audit_results_score_range",
    sql`score IS NULL OR (score >= 0 AND score <= 100)`,
  ),

```

### Discriminated-union CHECK constraint

Raw SQL in `migrations/0000_init.sql`, applied alongside the table DDL:

```sql
ALTER TABLE audit_results ADD CONSTRAINT audit_results_status_fields_consistent
  CHECK (
    (status = 'failed'
     AND score IS NULL AND issues IS NULL AND raw IS NULL
     AND error_code IS NOT NULL AND error_message IS NOT NULL
     AND error_retryable IS NOT NULL)
    OR
    (status IN ('success','partial')
     AND score IS NOT NULL AND issues IS NOT NULL
     AND error_code IS NULL AND error_message IS NULL
     AND error_retryable IS NULL
     AND (status = 'success' OR partial_reasons IS NOT NULL))
  );
```

Defense in depth on top of the Zod validation in `map.ts`.

## Triggers

Three triggers live in `migrations/0000_init.sql`, sourced from the per-trigger SQL files in `src/triggers/`.

### `handle_new_user` — auto-create profile row

```sql
CREATE FUNCTION public.handle_new_user() RETURNS trigger
LANGUAGE plpgsql SECURITY DEFINER SET search_path = public AS $$
BEGIN
  INSERT INTO public.profiles (id, display_name)
  VALUES (NEW.id, NEW.raw_user_meta_data->>'display_name');
  RETURN NEW;
END $$;

CREATE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE FUNCTION public.handle_new_user();
```

### `set_run_owner_from_site` — denorm trigger on `audit_runs`

```sql
CREATE FUNCTION set_run_owner_from_site() RETURNS trigger
LANGUAGE plpgsql AS $$
BEGIN
  IF NEW.owner_id IS NULL THEN
    SELECT owner_id INTO NEW.owner_id FROM sites WHERE id = NEW.site_id;
    IF NEW.owner_id IS NULL THEN
      RAISE EXCEPTION 'audit_runs.site_id % does not exist', NEW.site_id;
    END IF;
  END IF;
  RETURN NEW;
END $$;

CREATE TRIGGER audit_runs_set_owner
  BEFORE INSERT ON audit_runs
  FOR EACH ROW EXECUTE FUNCTION set_run_owner_from_site();
```

Same idea on `audit_results.owner_id` via lookup through `audit_runs`.

### `rollup_run_status` — derive `audit_runs.status` from results

```sql
CREATE FUNCTION rollup_run_status() RETURNS trigger
LANGUAGE plpgsql AS $$
DECLARE
  total int;
  failed int;
  partial int;
  expected int := 5;  -- slice 1 category count
BEGIN
  SELECT COUNT(*),
         COUNT(*) FILTER (WHERE status = 'failed'),
         COUNT(*) FILTER (WHERE status = 'partial')
    INTO total, failed, partial
    FROM audit_results WHERE run_id = NEW.run_id;

  UPDATE audit_runs SET
    status = CASE
      WHEN total < expected THEN 'running'
      WHEN failed > 0 THEN 'failed'
      WHEN partial > 0 THEN 'partial'
      ELSE 'completed'
    END,
    finished_at = CASE WHEN total >= expected THEN now() ELSE finished_at END,
    final_url = COALESCE(audit_runs.final_url, (NEW.raw->>'finalUrl')::text)
  WHERE id = NEW.run_id;

  RETURN NEW;
END $$;

CREATE TRIGGER audit_results_rollup
  AFTER INSERT ON audit_results
  FOR EACH ROW EXECUTE FUNCTION rollup_run_status();
```

The `expected := 5` constant migrates when slice 7 adds new audit packages.

## RLS policies

Enabled on `profiles`, `sites`, `audit_runs`, `audit_results`.

```sql
-- profiles
ALTER TABLE profiles ENABLE ROW LEVEL SECURITY;
CREATE POLICY "profiles_select_own" ON profiles
  FOR SELECT USING (id = (SELECT auth.uid()));
CREATE POLICY "profiles_update_own" ON profiles
  FOR UPDATE USING (id = (SELECT auth.uid()));

-- sites (full CRUD on own rows)
ALTER TABLE sites ENABLE ROW LEVEL SECURITY;
CREATE POLICY "sites_select_own" ON sites
  FOR SELECT USING (owner_id = (SELECT auth.uid()));
CREATE POLICY "sites_insert_own" ON sites
  FOR INSERT WITH CHECK (owner_id = (SELECT auth.uid()));
CREATE POLICY "sites_update_own" ON sites
  FOR UPDATE USING (owner_id = (SELECT auth.uid()));
CREATE POLICY "sites_delete_own" ON sites
  FOR DELETE USING (owner_id = (SELECT auth.uid()));

-- audit_runs (read + insert by owner; runner uses service role to bypass)
ALTER TABLE audit_runs ENABLE ROW LEVEL SECURITY;
CREATE POLICY "audit_runs_select_own" ON audit_runs
  FOR SELECT USING (owner_id = (SELECT auth.uid()));
CREATE POLICY "audit_runs_insert_own" ON audit_runs
  FOR INSERT WITH CHECK (owner_id IS NULL OR owner_id = (SELECT auth.uid()));

-- audit_results (read-only for owners; writes are service-role only)
ALTER TABLE audit_results ENABLE ROW LEVEL SECURITY;
CREATE POLICY "audit_results_select_own" ON audit_results
  FOR SELECT USING (owner_id = (SELECT auth.uid()));
-- No INSERT/UPDATE/DELETE policy: locked to service-role
```

Notes:
- `(SELECT auth.uid())` (not `auth.uid()`) lets Postgres hoist the call to once per query. Standard Supabase performance pattern.
- `service_role` has `BYPASSRLS` out of the box; the runner connects with `SUPABASE_SERVICE_ROLE_KEY` and bypasses all policies.
- No INSERT policy on `audit_results` blocks anon and authenticated roles from fabricating results.

Design principle: thin domain layer. The package exposes the Drizzle client and table schemas; it does not wrap every CRUD operation. Consumers write their own one-liner Drizzle queries against the exported `schema`. The only helpers we ship are the ones with non-trivial logic that must stay in lockstep with `@repo/audit-core`.

### `client.ts`

```ts
import { drizzle } from "drizzle-orm/postgres-js"
import postgres from "postgres"
import * as schema from "./schema/index.js"

export type DbClientOptions = {
  connectionString: string
  role?: "service_role" | "authenticated" | "anon"
  max?: number
  ssl?: "require" | "prefer" | false
}

export function createDbClient(opts: DbClientOptions) {
  const client = postgres(opts.connectionString, {
    max: opts.max ?? 10,
    ssl: opts.ssl ?? "prefer",
    prepare: false,                                 // Supabase pooler safety
  })
  return drizzle(client, { schema })
}

export type Db = ReturnType<typeof createDbClient>
```

`prepare: false` keeps things safe when running through Supabase's PgBouncer pooler.

### `map.ts`

```ts
import { AuditResultSchema, type AuditResult } from "@repo/audit-core"
import { auditResults, auditRuns } from "./schema/index.js"
import type { Db, NewAuditResultRow } from "./types.js"

export function auditResultToInsert(
  result: AuditResult,
  runId: string,
  ownerId: string,
): NewAuditResultRow {
  const parsed = AuditResultSchema.parse(result)

  const base: NewAuditResultRow = {
    runId,
    ownerId,
    category: parsed.category,
    status: parsed.status,
    packageName: parsed.packageName,
    packageVersion: parsed.packageVersion,
    durationMs: parsed.durationMs,
    startedAt: new Date(parsed.startedAt),
  }

  if (parsed.status === "success") {
    return { ...base, score: parsed.score, issues: parsed.issues, raw: parsed.raw }
  }
  if (parsed.status === "partial") {
    return {
      ...base,
      score: parsed.score,
      issues: parsed.issues,
      raw: parsed.raw,
      partialReasons: parsed.partialReasons,
    }
  }
  return {
    ...base,
    errorCode: parsed.error.code,
    errorMessage: parsed.error.message,
    errorRetryable: parsed.error.retryable,
  }
}

export async function insertAuditResult(
  db: Db,
  result: AuditResult,
  runId: string,
  ownerId: string,
): Promise<string> {
  const row = auditResultToInsert(result, runId, ownerId)
  const [inserted] = await db
    .insert(auditResults)
    .values(row)
    .returning({ id: auditResults.id })
  if (!inserted) throw new Error("audit_results insert returned no row")
  return inserted.id
}

export async function insertAuditRun(
  db: Db,
  input: { siteId: string; requestedUrl: string; triggeredBy?: "manual" | "scheduled" },
): Promise<string> {
  const [inserted] = await db
    .insert(auditRuns)
    .values({
      siteId: input.siteId,
      requestedUrl: input.requestedUrl,
      triggeredBy: input.triggeredBy ?? "manual",
    })
    .returning({ id: auditRuns.id })
  if (!inserted) throw new Error("audit_runs insert returned no row")
  return inserted.id
}
```

Pure mapping (`auditResultToInsert`) is decoupled from DB I/O so the runner can batch all 5 results into a single transaction.

### `normalize-url.ts`

```ts
const TRACKING_PARAMS = new Set([
  "utm_source", "utm_medium", "utm_campaign", "utm_term", "utm_content",
  "gclid", "fbclid", "ref",
])

export function canonicalUrl(input: string): string {
  let u: URL
  try {
    u = new URL(/^https?:\/\//i.test(input) ? input : `https://${input}`)
  } catch {
    throw new Error(`canonicalUrl: not a valid URL: ${input}`)
  }
  u.hash = ""
  u.username = ""
  u.password = ""
  u.hostname = u.hostname.toLowerCase()
  for (const p of [...u.searchParams.keys()]) {
    if (TRACKING_PARAMS.has(p.toLowerCase())) u.searchParams.delete(p)
  }
  if (u.pathname !== "/") u.pathname = u.pathname.replace(/\/+$/, "")
  return u.toString()
}
```

Centralized in `@repo/db` so the runner, the dashboard, and any future graph-analytics queries agree on the canonicalization.

## Testing strategy

| Layer | Tool | Approach |
|---|---|---|
| Unit: `canonicalUrl` | `vitest` | ~12 fixture cases: scheme inference, lowercase host, fragment, UTM stripping, trailing-slash, port preservation, IDN. |
| Unit: `auditResultToInsert` | `vitest` | One test per discriminator variant (success/partial/failed); validates against `NewAuditResultRow` shape; rejects malformed AuditResult via `AuditResultSchema.parse`. |
| Integration: RLS | `vitest` (gated `RUN_INTEGRATION=1`) | Spin up local Supabase, apply migrations, create 2 test users via Supabase Auth admin API, assert tenant isolation across all 4 tables. |
| Integration: triggers | `vitest` (gated) | Insert run + N results; assert `audit_runs.status` rollup transitions through `queued → running → partial|completed|failed`; assert `owner_id` denorm trigger fires and rejects orphan inserts. |
| Integration: insert helpers | `vitest` (gated) | End-to-end: `insertAuditRun` then `insertAuditResult × 5`; assert all 5 land, status is `completed`/`partial`/`failed` per the cases. |

### `integration/helpers.ts`

- Reads `DATABASE_URL` from the local Supabase stack env.
- Applies a fresh migration set to a randomly-named Postgres schema (so parallel test runs do not conflict).
- Creates two test users via the Supabase Auth admin API and returns Drizzle clients scoped per user (one anon/JWT-bound, one service-role).
- Tears the schema down in `afterAll`.

Alternative considered: `pgtap` for declarative RLS tests. Deferred — `vitest` + the Supabase Auth admin client covers slice 2's surface area and keeps the test stack uniform with the rest of the repo.

## After slice 2

Slice 3 (runner app + pgmq + Realtime broadcast) consumes the surface defined here. The `AuditResult → row` mapping is the only contract slice 3 needs from slice 2; everything else is just Drizzle queries the runner code writes inline.
